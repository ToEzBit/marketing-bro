# 0002 — permission model: `acceptEdits` + allowlist คำสั่ง shell ของเราเอง

Status: accepted (2026-07-30)

## Context

บอทให้สิทธิ์ระดับ "นั่งอยู่หน้าเครื่อง host" ต้องหาสมดุลระหว่างความปลอดภัยและความลื่นไหล
ถ้าขออนุมัติทุกอย่าง งาน dev จะช้าจนใช้ไม่ได้ ถ้าไม่ขอเลยก็เสี่ยงเกินรับ ทางเลือก:

1. `permissionMode: 'default'` — Claude Code ถามทุกการแก้ไฟล์และทุกคำสั่ง → ปุ่มเด้งรัวจนใช้งานจริงไม่ได้
2. `permissionMode: 'bypassPermissions'` — ไม่ถามเลย → เสี่ยงเกินไปสำหรับเครื่องที่ใช้ทำงานจริง
3. `acceptEdits` + allowlist ของเราคุม Bash ผ่าน `canUseTool`

## Decision

เลือกทางที่ 3:

- `permissionMode: 'acceptEdits'` — แก้ไฟล์ใน workspace ผ่านเลย
- `canUseTool` รับทุกเคสที่ Claude Code จะถาม แล้ว `src/policy.ts` ตัดสินอีกชั้น:
  คำสั่ง shell แบบอ่านล้วนผ่านอัตโนมัติ ที่เหลือส่งขึ้นปุ่มใน Discord
- Allowlist ตรวจถึงระดับ flag ด้วย เพราะคำสั่งที่อยู่ใน allowlist เองยังเขียนไฟล์ได้
  (`find -exec`, `sort -o`, `git branch -D`, `git tag v1`, `git remote add`)

## Verification

สมมติฐานสองข้อที่โครงสร้างนี้พึ่งพา ทดสอบด้วยการรัน SDK จริงแล้ว:

1. **`acceptEdits` ไม่ครอบไฟล์นอก cwd** — สั่งให้เขียนไฟล์นอก workspace แล้ว `canUseTool`
   ถูกเรียกจริง (ไม่ได้ผ่านเงียบ) และเมื่อ deny ไฟล์ไม่ถูกสร้าง ถ้าผลออกตรงข้าม
   สาขา Write→ask ใน policy จะเป็นโค้ดตายและขอบเขตไฟล์จะไม่มีอยู่จริง
2. **`env: { ANTHROPIC_API_KEY: undefined }` ลบตัวแปรจริง** — ตั้งคีย์ปลอมไว้ใน
   process แล้ว agent ยังทำงานได้ แสดงว่าคีย์ถูกลบ ไม่ได้ถูกส่งเป็นค่าว่าง
   ถ้าผลออกตรงข้าม เครื่องที่มี `ANTHROPIC_API_KEY` จะถูกเก็บเงินแบบ API เงียบ ๆ
   ซึ่งขัดกับข้อบังคับหลักของโปรเจกต์

## Consequences

- ✅ งาน dev ทั่วไป (อ่านโค้ด แก้ไฟล์ รันเทสต์ ดู git) ไหลลื่นไม่มีปุ่มขัด
- ✅ การกระทำที่ย้อนยากทุกอย่างมีมนุษย์กดยืนยัน
- ⚠️ Allowlist เป็นงานที่ต้องดูแลต่อ ทุกครั้งที่เพิ่มคำสั่งต้องถามว่า flag ไหนเขียนได้
  `src/policy.test.ts` เป็นที่บันทึกขอบเขตนี้ — เพิ่มเทสต์ก่อนแก้ allowlist
- ⚠️ `npm test` / `pytest` / `go test` / `cargo test` ผ่านอัตโนมัติ = โค้ดในโปรเจกต์
  ถูกรันได้โดยไม่ถาม เป็นการแลกที่ตั้งใจ ถอดออกได้ถ้าไม่ยอมรับความเสี่ยงนี้
- ⚠️ ผูกกับพฤติกรรม `acceptEdits` ของ Claude Code ถ้าเวอร์ชันใหม่เปลี่ยนขอบเขต
  ต้องรันการทดสอบข้อ 1 ซ้ำ
