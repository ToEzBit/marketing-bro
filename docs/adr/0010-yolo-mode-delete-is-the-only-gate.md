# 0010 — YOLO_MODE: การลบเป็นด่านเดียวที่เหลือ

Status: accepted (2026-08-17)

## Context

ADR 0002 เลือก allowlist คำสั่งอ่านล้วน + ปุ่ม Approval สำหรับที่เหลือ หลังใช้จริงมาระยะหนึ่ง
ADR 0008 เจาะรูแรกให้ browser เพราะ deployment นี้เป็น **Operator คนเดียว** — คนกดอนุมัติกับคนสั่งงาน
เป็นคนเดียวกัน การอนุมัติตัวเองจึงเป็น friction ล้วน

Operator ประเมินแล้วว่าเหตุผลเดียวกันนี้ใช้ได้กับเกือบทุกคำสั่ง: `npm run build`, `git commit`,
`docker compose up` ฯลฯ ไม่มีอันไหนที่การกดปุ่มยืนยันช่วยตัดสินใจอะไรจริง มีเพียงกรณีเดียวที่ปุ่ม
ยังมีค่า คือ **การลบ** เพราะเป็นการกระทำที่กด undo ไม่ได้และ agent เผลอทำได้ง่ายที่สุด

## Decision

- เพิ่ม env **`YOLO_MODE`** (ค่าเริ่มต้น **ปิด**) — เมื่อเปิด `decide()` กลับขั้วจาก
  "อะไรปลอดภัยบ้าง" เป็น "อะไรทำลายของบ้าง": ทุก tool call ใน Task ผ่านอัตโนมัติ
  ยกเว้นสิ่งที่ `isDestructiveBash()` จับได้ ซึ่งยังขึ้นปุ่มเหมือนเดิม
- **ขอบเขตของ "ลบ"** = ลบไฟล์ตรง ๆ + ล้างงานที่ยังไม่ commit (Operator เลือกขอบเขตนี้เอง):
  `rm` `rmdir` `unlink` `shred` `srm` `truncate` · `git clean` (ยกเว้น `-n`/`--dry-run`)
  `git rm` `git reset --hard` `git checkout <path>` `git restore` (ยกเว้น `--staged` เดี่ยว)
  `git stash drop|clear` · `find -delete` และ exec predicates · `rsync --delete*` · `dd of=`
- **การแก้ไขไฟล์ไม่ใช่การลบ** และต้องไม่ติดด่านนี้ — `Edit`/`Write`, `sed -i`, `>>` และ
  **`>` (redirect ทับไฟล์) ผ่านทั้งหมด** เหตุผลของ `>`: `acceptEdits` ปล่อยให้ `Write` เขียนทับไฟล์
  ได้ฟรีอยู่แล้ว ดัก `>` จึงได้ friction โดยไม่ได้ความปลอดภัยเพิ่ม
- **สแกนทุก segment ของคำสั่ง** ด้วย `CHAIN_OPERATORS` ตัวเดียวกับ allowlist เดิม
  (`npm test && rm -rf dist` ต้องถาม) และถอด wrapper (`sudo`, `xargs`, `env`, `nohup`, `do`)
  ก่อนดูชื่อคำสั่งจริง
- **`YOLO_MODE` ครอบ `BROWSER_AUTO_APPROVE` ให้ในตัว** — ไม่สร้างกลไกที่สอง
  `browser_file_upload` ผ่าน (อัปโหลดไม่ได้ลบอะไรบนเครื่อง) แต่ **`browser_run_code_unsafe`
  ยังถามเสมอ** เพราะรันโค้ดที่ policy มองไม่เห็น ซึ่งคือทางลบไฟล์ที่ตรงที่สุด
- **Scheduled Run ปฏิเสธการลบเสมอ ไม่ผูกกับ flag** — ADR 0004 บังคับให้ตัดสิน allow/deny ทันที
  เพราะไม่มีคนกดปุ่ม กติกา "การลบต้องมีมนุษย์" ในบริบทที่ไม่มีมนุษย์จึงแปลได้ทางเดียวคือ deny
- **ถอด `EXTRA_BASH_ALLOW` ออกทั้งกลไก** (ยกเลิกส่วนหนึ่งของ ADR 0008) — สองเหตุผล:
  1. **ซ้ำซ้อน**: วัดแล้วว่าเมื่อเปิด `YOLO_MODE` ทุกรายการใน list ของ Operator
     (`cp,mv,mkdir,date,TZ=… date`) ตัดสินเหมือนกันเป๊ะทั้งมีและไม่มี list — และ `date`
     อยู่ใน `BASH_ALLOWLIST` พื้นฐานอยู่แล้ว
  2. **เป็นทางลัดรอบด่านลบ**: `isReadOnlyBash()` ถูกเช็คก่อน `isDestructiveBash()` เสมอ
     ดังนั้น `EXTRA_BASH_ALLOW=rm` (หรือ `git`, `find`) ทำให้ `rm -rf x` กลายเป็น allow
     **ทั้งที่เปิด YOLO และปิด YOLO** — ยืนยันด้วยการรันจริงแล้ว กติกาข้อเดียวของ ADR นี้
     จึงถูกปิดได้ด้วยการเติมคำเดียวใน `.env` โดยไม่มีอะไรเตือน
  แทนที่ด้วย invariant ใน `policy.test.ts`: **ไม่มีคำสั่งทำลายตัวไหนผ่านทาง allowlist ได้เลย**
  (สแกนทั้งชุด — ถ้าวันหลังมีคนเติมคำสั่งที่ลบไฟล์ได้เข้า `BASH_ALLOWLIST` เทสต์จะแดง)
- **`permissionMode` ยังเป็น `acceptEdits` เหมือนเดิม ห้ามเปลี่ยนเป็น `bypassPermissions`**
  ถ้าเปลี่ยน `canUseTool` จะไม่ถูกเรียกเลย ด่านลบจะกลายเป็นโค้ดตาย **โดยที่ `npm test` ยังเขียว**
  (เทสต์เรียก `decide()` ตรง ๆ) — เป็นโหมดพังที่เงียบที่สุดของการตัดสินใจนี้

## Considered Options

- **`permissionMode: 'bypassPermissions'`** — คือทางเลือกที่ 2 ที่ ADR 0002 ปัดตกไปแล้ว
  ปัดตกซ้ำ: มันข้าม `canUseTool` ทั้งหมด จึงเก็บข้อยกเว้นเรื่องการลบไว้ไม่ได้เลย
- **เอา `rm` เข้า `EXTRA_BASH_ALLOW` แล้วปล่อยที่เหลือตามเดิม** — ปัดตก: ได้ผลตรงข้ามกับที่ต้องการ
  (อนุญาตการลบ แต่ยังถามเรื่องอื่น)
- **ทำเป็นค่าเริ่มต้นเลย ไม่ต้องมี flag** — ปัดตก: deployment ที่มีหลาย Member ยังต้องการด่านเดิม
  ค่าเริ่มต้นต้องปลอดภัยไว้ก่อน (หลักเดียวกับ ADR 0008)
- **ดักการลบให้ครบจริง ๆ โดยถามทุกครั้งที่เจอ interpreter หรือสคริปต์** (`python -c`, `bash x.sh`,
  `$(...)`) — ปัดตก: นั่นคือการสร้าง friction กองใหม่กลับมาแทนกองเดิม ซึ่งขัดกับเหตุผลทั้งหมด
  ของการตัดสินใจนี้ ยอมรับว่าด่านนี้ดักได้ไม่ครบแทน แล้วเขียนรูไว้ให้ชัด (ดู Consequences)

## Consequences

- ✅ งานประจำวันไม่มีปุ่มขัดเลย — build, test, commit, push, docker, สคริปต์ของโปรเจกต์
- ✅ อุบัติเหตุที่แพงที่สุดและพบบ่อยที่สุด (`rm -rf` ผิดที่, `git reset --hard` ทับงานที่ยังไม่ commit)
  ยังมีมนุษย์คั่นอยู่
- ✅ Scheduled Run ปลอดภัยขึ้นกว่าเดิม — เมื่อก่อน Bash ทุกคำสั่งรวมทั้ง `rm -rf` ผ่านด้วย Grant
- ⚠️ **นี่คือกันพลาด ไม่ใช่กำแพงกันภัย** ด่านนี้อ่านคำสั่งตามตัวอักษร รูที่รู้ตัวและยอมรับ:
  - `$(...)` / backtick / `eval` — เนื้อคำสั่งจริงไม่ได้อยู่ในข้อความที่สแกน
  - interpreter: `python -c "os.remove(...)"`, `node -e "fs.rmSync(...)"`, `perl -e ...`
  - สคริปต์: `bash cleanup.sh`, `./deploy.sh`, `npm run clean` — agent เขียนสคริปต์เองแล้วรันได้
  - `Write` ทับไฟล์เดิมจนเนื้อหาเดิมหาย (ตั้งใจให้ผ่าน — ดู Decision)
  - `git branch -D` ลบ branch (ไม่ใช่ไฟล์ จึงอยู่นอกขอบเขตที่ Operator เลือก — reflog กู้ได้)
  - **สรุป: ถ้า agent ตั้งใจลบ มันลบได้** ด่านนี้กันแค่การเผลอในคำสั่งที่เขียนตรง ๆ
- ⚠️ `YOLO_MODE` ให้ **ทุก Member ใน `ALLOWED_USER_IDS`** มีสิทธิ์ระดับนี้ วันนี้ไม่มีผลเพราะ
  operator คนเดียว — **ต้องทบทวน flag นี้ก่อนเพิ่มคนใน `ALLOWED_USER_IDS` ทุกครั้ง**
  (ข้อบังคับเดียวกับ ADR 0008 และ flag ทั้งสองตัวต้องทบทวนพร้อมกัน)
- ⚠️ ถอด `EXTRA_BASH_ALLOW` แล้ว **ตอน `YOLO_MODE=false` จะถามบ่อยขึ้นกว่าเดิม** — `cp`, `mv`,
  `mkdir` กลับไปขึ้นปุ่มทุกครั้ง เพราะไม่มีช่องให้เติมคำสั่งเองอีกแล้ว deployment ที่ต้องการ
  ผ่อนตรงนี้เหลือทางเดียวคือเปิด `YOLO_MODE` (ซึ่งผ่อนกว่ามาก) หรือแก้ `BASH_ALLOWLIST` ในโค้ด
  ให้มีเทสต์ประกบ — **ตั้งใจให้เป็นแบบนั้น**: การผ่อนสิทธิ์ควรอยู่ในโค้ดที่รีวิวได้
  ไม่ใช่ในสตริงของ `.env` ที่ไม่มีใครเห็น
- ⚠️ `mv` กับ `cp` ยัง**ไม่ถูกนับเป็นการลบ** — `mv drafts/สำคัญ.md /tmp/` ทำให้ไฟล์หายไปจาก
  ที่เดิมโดยไม่ขึ้นปุ่ม (ผ่านทาง YOLO) และ workspace จริงของ Operator ไม่ได้อยู่ใต้ git
  จึงไม่มีประวัติให้กู้ — รู้ตัวแล้วแต่ยังไม่ตัดสิน เพราะขอบเขต "ลบ" ที่ Operator เลือกไว้
  ไม่รวมการย้าย/เขียนทับ ถ้าจะเปลี่ยนต้องแก้ ADR นี้
- ⚠️ false positive ที่ยอมรับ (ผิดฝั่งที่ปลอดภัยไว้ก่อน): `git checkout feature/x` — branch ที่มี `/`
  ในชื่อจะถูกถาม เพราะ git เองก็แยก branch กับ path ไม่ได้ถ้าไม่เปิดดู repo · `truncate -s +1M x`
  (ขยายไฟล์) ก็ถูกถาม เพราะนับ `truncate` เป็นคำสั่งทำลายทั้งตัวโดยไม่ดูแฟล็ก
- Scheduled Run ฝั่ง browser (`decideScheduledBrowser`) **ไม่แก้** — ยังเป็นกติกาเดิมของ ADR 0004
  (Grant คลุมทุกอย่างรวม upload, `browser_run_code_unsafe` ปิดตาย) การลบผ่าน browser ไม่ใช่
  ทางที่มีอยู่จริง ส่วนทางที่มี (`run_code_unsafe`) ถูกปิดอยู่แล้วตั้งแต่ต้น
- `src/policy.test.ts` บันทึกขอบเขตนี้ไว้ (ยืนยันแล้วว่าถอด `isDestructiveBash` ออกแล้วเทสต์แดง
  33 ข้อ) — แก้รายการคำสั่งเมื่อไรต้องเพิ่มเทสต์ก่อน ตามข้อบังคับของ ADR 0002
