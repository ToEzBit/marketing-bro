# 0009 — Office UI ปิดขอบเขตที่สภาพหลัง #27

Status: accepted (2026-08-17)

## Context

Office UI (หน้าเว็บ read-only ตาม ADR 0002) ส่งมอบครบใน #23 แล้วเก็บงานภาพต่ออีกสามรอบ
(#25 asset, #26 ป้าย/เต็มจอ, #27 นั่งเก้าอี้จริง + คิว Browser + `+n` คลิกได้) ตอนนี้ฟีเจอร์ใช้งานได้ครบ
`npm test` เขียว และเจ้าของโปรเจกต์ตัดสินใจ **ไม่พัฒนาเพิ่ม**

ท้าย PR #27 มีหัวข้อ "ที่ยังไม่สวย และเหตุผลที่ไม่ตัดสินใจเอง" 4 ข้อ ที่ agent เลือกไม่ตัดสินเอง
ทั้งสี่ข้อไม่ใช่บั๊ก แต่เป็น **ข้อแลกเปลี่ยนที่ชนเพดานพื้นที่จริงของห้อง** — ปล่อยค้างไว้ใน body ของ PR
จะถูกหยิบมาแก้ใหม่รอบแล้วรอบเล่า เพราะไม่มีใครอ่าน PR ที่ merge ไปแล้วก่อนแตะโค้ด

## Decision

- **Office UI ปิดขอบเขตที่สภาพที่ merge ใน #27** — ยังเป็น read-only ตาม ADR 0002 ยังเปิด/ปิดด้วย
  `OFFICE_UI_PORT` เหมือนเดิม ไม่มีการถอดโค้ดหรือปิดฟีเจอร์ใด ๆ ("ไม่ทำเพิ่ม" ไม่ใช่ "ไม่ใช้")
- **4 ข้อทัศนวิสัยท้าย PR #27 = won't fix** ไม่ใช่ backlog — ตัวเลขข้อจำกัดของแต่ละข้ออยู่ใน Consequences
- **งานที่ยังรับต่อมีสองอย่างเท่านั้น**: (1) บั๊ก — หน้าเว็บพัง, snapshot บอกความจริงผิด, เทสต์แดง
  (2) ตามการเปลี่ยนแปลงของ state model ฝั่งบอท — **เฉพาะเมื่อบอทเพิ่มสถานะ/โซนใหม่จริงจนไม่มีที่ยืนในห้อง
  ไม่ใช่การปรับของเดิมให้ดูดีขึ้น** งานปรับความสวยล้วนไม่อยู่ในสองข้อนี้
- **คำถามค้างเรื่อง asset ใน `docs/research/office-pixel-assets.md` §7 ปิดครบแล้ว** — ดิสโพสิชันเขียนกำกับไว้
  ในไฟล์นั้นทีละข้อ (resolved / moot / won't do) เรื่อง license ของแพ็กที่ใช้จริงยืนยันครบใน
  `office/assets/default/CREDITS.md` §2 แล้ว

## Considered Options

- **ปล่อย 4 ข้อไว้ท้าย PR เฉย ๆ** — ปัดตก: PR ที่ merge แล้วไม่ใช่ที่ที่ใครอ่านก่อนแตะโค้ด ข้อที่เขียนว่า
  "ยังไม่สวย" อ่านเป็น "ยังไม่ได้ทำ" เสมอ
- **เปิดเป็น issue backlog** — ปัดตก: issue ที่เปิดค้างคือคำเชิญให้ทำ ซึ่งตรงข้ามกับการตัดสินใจนี้
- **ถอดฟีเจอร์ทิ้ง (เอา `OFFICE_UI_PORT` ออก)** — ปัดตก: ของใช้งานได้และใช้อยู่จริง

## Consequences

4 ข้อนี้เป็นสภาพถาวรของห้อง ไม่ต้องรื้อ ไม่ต้องรายงานซ้ำ — ตัวเลขคือเหตุผลที่มันเป็น won't fix ไม่ใช่ not yet:

- **ผู้ถือ Browser ยืน ไม่ได้นั่งเก้าอี้** — โซนสูง 6 tile ต้องเรียง ตัวผู้ถือ → ป้าย → ตัวในคิว → ป้าย
  รวม **~153px ในที่ว่าง ~150px** ถ้าดันผู้ถือลงไปนั่งเบาะ ป้ายของมันจะคลุมหัวตัวในคิวเต็ม ๆ
  ทางออกเดียวคือตัดช่องคิวเหลือช่องเดียว = เสียข้อมูลว่าใครรออยู่บ้าง ซึ่งแพงกว่าท่ายืน
- **คิว Browser ช่องที่ 2 ไม่มีเก้าอี้รองรับ** — เก้าอี้จริงในผังห้องสองคอลัมน์ห่างกัน **2 tile**
  ซึ่งแคบกว่ากล่องป้าย (**2.75 tile**) วางคนสองคนบนเก้าอี้จริงแล้วป้ายจะทับกันแน่นอน
- **โซน stopped / bug ไม่ได้นั่งเก้าอี้จริง** — เก้าอี้ของโซนนั้นอยู่ **row 11** ถ้าลงไปนั่ง ป้ายต้องพลิกขึ้นบน
  แล้วไปทับแถบ marker `Schedule auto-pause` ซึ่งเป็นข้อมูลสถานะ ไม่ใช่ของตกแต่ง
- **ที่นั่ง lounge ขนาบโซฟา ไม่ได้นั่งบนโซฟา** — ที่นั่งทุกโซนคำนวณจาก rect ของ `zones` ตาม spec §7.2
  ที่ห้าม hard-code พิกัด การให้นั่งบนโซฟาพอดีต้องผูกโค้ดเข้ากับผังห้องชุด default ตัวเดียว
  แล้ว `custom/` ของ Operator จะพังทันที

ถ้าวันหนึ่งจะรื้อข้อไหนจริง ต้องล้มตัวเลขข้างบนให้ได้ก่อน (เช่น ออกแบบป้ายให้เตี้ยลงจนสูงรวมต่ำกว่า 150px,
ขยายโซนในผังห้อง, หรือเปลี่ยน spec §7.2) ไม่ใช่ "ลองขยับดูอีกที" — และต้องเขียน ADR ใหม่ทับ ADR นี้
