# 0012 — เลิก browser grant: Scheduled Run ใช้ browser ได้เสมอ

Status: accepted (2026-08-19)

แทนที่ข้อ "Browser ต้องเลือกมอบเพิ่มตอนสร้าง" ของ [ADR 0004](./0004-scheduled-runs-use-grants.md) ส่วนที่เหลือของ 0004 ยังอยู่ครบ

## Context

ADR 0004 ย้ายจุดอนุมัติของงานตั้งเวลาจาก "ตอนรัน" ไป "ตอนสร้าง" แล้วแยก browser ออกมาเป็นสิทธิ์ที่ต้องเลือกมอบต่างหาก (`browser:true`) ด้วยเหตุผล least privilege: schedule สายรายงานที่ไม่ใช้เว็บไม่ควรถือสิทธิ์บัญชีที่ล็อกอินค้างไว้ฟรี ๆ

สิ่งที่เกิดขึ้นจริงหลังใช้งาน:

- บอทตัวนี้เป็นบอทของ Operator คนเดียว (`ALLOWED_USER_IDS` ว่าง) และเปิด `YOLO_MODE` ไว้ ซึ่งแปลว่าใน Task ทุกอย่างผ่านหมดยกเว้นคำสั่งลบ (ADR 0010) — การบังคับให้ Run ต้องขอสิทธิ์ browser แยกอีกชั้น จึงเป็นด่านที่ไม่ตรงกับระดับความเชื่อใจที่เจ้าของตั้งไว้เองแล้ว
- โหมดพังของการลืมใส่คือ **schedule ที่ทำงานไม่ได้แบบเงียบ ๆ** — ทุกรอบโดน deny แล้วรายงานว่าไม่มีสิทธิ์ ไม่มีใครสังเกตจนกว่าจะไปเปิดเธรดอ่าน และ pipeline ทั้งสายต้องมอบสิทธิ์นี้อยู่แล้วทุกตัว ยกเว้น janitor
- ค่านี้เป็น boolean ที่ต้องดูแลต่อ schedule ทั้งที่คำตอบเกือบทุกครั้งคือ "ใช่"

## Decision

- **ถอด `browser:` ออกจาก `/schedule create` และ `/schedule edit`** และเลิกเก็บ `browserGrant` ใน record
- **ทุก Scheduled Run แตะ browser ได้เสมอ** โดยไม่ต้องมอบอะไร (ยังเข้าคิว FIFO ตัวเดียวกับทุกคนตาม ADR 0006 เหมือนเดิม)
- **สิ่งที่ยังถูกปฏิเสธเสมอใน Run ไม่เปลี่ยน**: เขียนไฟล์นอก Workspace และ `browser_run_code_unsafe` (รันโค้ดระดับ Host) — สองข้อนี้เป็นเพดานของ ADR 0004 ที่ยังยืนอยู่

## Considered Options

- **คงไว้เหมือนเดิม** — ได้ least privilege ต่อ schedule แต่แลกกับ boolean ที่ตอบว่า "ใช่" เกือบทุกครั้ง และโหมดพังแบบเงียบเมื่อลืม
- **ให้ `YOLO_MODE` เติม `browser:true` ให้อัตโนมัติ** — ลด friction โดยยังเก็บ grant เป็นรายตัวไว้ให้ถอนได้ แต่กลายเป็นสองสถานะที่ต้องเข้าใจ (ค่าที่พิมพ์เอง vs ค่าที่ระบบเติม) และยังลืมได้อยู่ดีตอน YOLO ปิด — ถูกปัดตกเพราะซับซ้อนขึ้นโดยไม่ได้ปิดโหมดพังจริง

## Consequences

- ⚠️ **ความเสี่ยงที่ ADR 0004 บันทึกไว้ ตอนนี้ครอบทุก schedule ไม่ใช่เฉพาะตัวที่ถูกมอบ**: schedule ที่ไปอ่านเนื้อหาเว็บภายนอกอาจโดน prompt injection ให้ใช้บัญชีที่ล็อกอินค้างทำสิ่งที่ไม่ได้ตั้งใจตอนไม่มีใครดู — และ schedule ที่ไม่มีเหตุผลต้องใช้เว็บเลย (เช่น janitor) ก็ถือสิทธิ์นั้นไปด้วย
- เบรกที่เหลือคือชุดเดิมของ ADR 0004: activity log ในเธรดถาวร, `pause` ที่ทุกคนกดได้, auto-pause เมื่อล้ม 3 รอบติด และคิว browser ตัวเดียวที่เห็นได้จาก `/status`
- **ต้องกลับมาทบทวน ADR นี้ถ้าบอทเลิกเป็นบอทของคนเดียว** — เหตุผลที่รับความเสี่ยงนี้ได้คือคนสร้าง schedule กับเจ้าของบัญชีในบราวเซอร์เป็นคนเดียวกัน ถ้า `ALLOWED_USER_IDS` มีคนอื่นเมื่อไร ข้อสมมตินั้นหายไป
- record เก่าที่มี `browserGrant` ค้างในไฟล์ state ไม่ต้องแปลง — ไม่มีใครอ่านมันอีกแล้ว
